**Structure:** README Style
1. **Project Title & one-line description** – What it does, in one sentence.
2. **Badges** (optional) – Build status, license, version, etc., if conventional for the tech stack found during research.
3. **Features** – Short bullet list of key capabilities.
4. **Installation** – Exact commands (`pip install`, `npm install`, etc.) in fenced code blocks.
5. **Usage / Quick Start** – A minimal, runnable code example in a fenced code block with the correct language tag.
6. **Configuration** – Environment variables, config files, or flags, if relevant.
7. **Project Structure** (optional) – A short file/folder tree if it aids understanding.
8. **Contributing** – A brief, standard note on how to contribute.
9. **License** – State the license type (ask for it in the content if not specified, defaulting to noting "add your license here").

**Voice:** Clear, neutral, professional technical documentation. **Do NOT use viral hooks, a "Spiky POV," a quiz, emojis-as-decoration, or a debate-style CTA** — this is reference material, not persuasive content.
